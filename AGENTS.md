# Правила работы над Psy AI Admin

Файл читается агентами перед началом работы. Всё ниже — не пожелания, а
следствия измерений: каждое правило появилось после того, как его нарушение
что-то сломало.

## Что это за проект

Безопасный AI-администратор для психологического центра. Один движок, два
продукта, каталоги вместо копий кода.

```
engine/       движок: границы безопасности, маршрутизация, поиск, модель
hosted-demo/  публичная витрина (Next.js + Cloudflare Worker), маршрут в браузере
v2/           серверный продукт: запись на консультации, панель менеджера, голос
eval/         наборы проверочных вопросов и метрики
docs/         замеры и разборы
```

Арендатор описывается каталогом (`hosted-demo/app/center-content.json`,
`v2/config/assistant.json`): страницы, тексты, порядок правил, FAQ. Новый
заказчик — это новый каталог, а не форк.

## Шесть правил, которые нельзя нарушать

**1. Безопасность идёт до тем.** Первый шаг `pipeline` обязан быть
`{"safety": "crisis"}`; каталог без него не запускается. Правило арендатора не
может встать перед кризисной проверкой — на это есть тест.

**2. Модель выбирает, а не сочиняет.** Языковая модель называет раздел или
признаёт незнание; текст ответа остаётся заранее написанным. Как только модель
начнёт формулировать ответ сама, весь набор проверок перестанет измерять
продукт: он проверяет выбор страницы, а не содержание фразы. Захотите
сочинение — сначала новая проверка «не вышел ли текст за пределы источника»,
и лучше на личном сайте, а не на сайте центра.

**3. Неподтверждённое не произносится.** Запись `faq` звучит только при
`confirmed: true`, и такая запись обязана назвать `confirmedOn` и `confirmedBy`.
Без них каталог не запускается. Сейчас все семь помечены «разработчик проекта;
подтверждение центра не получено» — лист для центра в
[`docs/faq-confirmation.md`](docs/faq-confirmation.md).

**4. Отложенный набор расходуется.** Как только его промахи привели к правке
кода, он перестаёт быть независимым: `role` меняется на `regression`, `burned`
фиксирует дату и причину, пишется следующий набор. Так уже произошло шесть раз.
Замер качества берётся только из набора с `role: heldout`. Подгонять ожидания
под поведение роутера нельзя.

**5. Не заявлять неизмеренное.** Каждое утверждение о качестве должно иметь
прогон. Если механизм не даёт выигрыша — он не едет в поставку, даже если
выглядит современно: так поиск по документам был выключен на месяц, пока не
появился материал, и так же удалена «мягкая страховка» на кризис.

**6. Предупреждение об экстренных контактах видно всегда.** Не по
распознаванию, а постоянно, рядом с полем ввода — в витрине и в v2. Ни один
классификатор не даёт полноты, на которую можно опереться вместо него.

## Как проверять

```bash
npm test              # 78 тестов: движок, витрина, v2, наборы
npm run eval          # прогон всех наборов, печатает независимый замер
npm run eval:report   # то же + отчёт в docs/evaluation-baseline.md
```

Сравнить шаблоны и модель одним набором:

```bash
node eval/run.mjs --only hosted,selector --dataset heldout7
```

Адаптеры: `hosted` (только шаблоны, с него снимается планка),
`model` (плюс распознавание кризиса), `selector` (плюс выбор раздела),
`selector-only` (без BM25). Три последних требуют `LLM_BASE_URL`.

## Где мы сейчас

Действующий независимый набор — `heldout7` (маршрутизация), `heldout6`
(безопасность, уже сгорел).

| | Только шаблоны | Шаблоны + модель |
|---|---:|---:|
| Маршрут, `heldout7` | 13/24 (54%) | 18/24 (75%) |
| Кризис, `heldout6` | 0 из 6 | 6 из 6 |

Списки шаблонов не обобщаются: четыре раунда пополнения не сдвинули
распознавание кризиса на новых формулировках. Разбор —
[`docs/crisis-detection-limits.md`](docs/crisis-detection-limits.md).

Мозг настраивается тремя переменными: `LLM_BASE_URL`, `LLM_API_KEY`,
`LLM_MODEL`. Адрес на `/v1` читается как OpenAI-совместимый, иначе как нативный
Ollama (её `/v1` не умеет отключать рассуждения: 13 секунд и пустой ответ
против 400 мс). Без `LLM_BASE_URL` мозг выключен.

## Чего не делать

- **Не включать модель и голос в витрине.** Она считает маршрут в браузере и до
  локальной модели не дотягивается. Улучшения живут в `v2`.
- **Не выкладывать панель менеджера в интернет.** Пароль один и общий, журнала
  действий нет; модель угроз — в [`v2/README.md`](v2/README.md).
- **Не писать формулировки интерфейса по пересказу из чужих сессий.** Источник
  утверждений о данных — условия обработки данных провайдера и владелец.
- **Не делать здесь «говорящую девочку» для личного сайта.** Это отдельный
  проект; здесь — скин психолога.
- **Не чинить регулярку, не добавив контрольный вопрос.** Подстрочные ловушки
  уже ловили: `зал` совпадал внутри «сказал», `почт` внутри «почти».

## Открытые вопросы

1. **Мозг «через Дхарму».** В опубликованном контракте Dharma AI
   inference-эндпоинта нет: ни chat/completions, ни имён моделей; BYOK — это
   credential-free federation, где `runtimeUrl` сообщаете вы, а обратно адрес не
   возвращается. Единственное рабочее прочтение: инференс идёт в собственный GCP
   владельца по гугловым реквизитам, а Дхарма стоит сверху как управление.
   Нужен прямой ответ владельца.
2. **Подтверждение FAQ центром.** Семь формулировок ждут ответа «верно /
   исправить / только ссылка» и решения по вместимости зала.
3. **Публикация витрины.** Изменения живут в репозитории; публичная страница
   обновляется через `git subtree push --prefix=hosted-demo demo-sites main`.

## Следующие задачи

- перевести настройку витрины на серверный маршрут, если появится удалённый
  синхронный эндпоинт: тогда витрина получит и распознавание кризиса, и выбор
  раздела;
- каталог для `aka-gst.ru` — третий арендатор на том же движке;
- проверка «ответ не вышел за пределы источника», если понадобится сочинение.
